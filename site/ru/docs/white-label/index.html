Документация

White label

Изменение заголовка, девиза, логотипа и палитры интерфейса через один YAML-файл.

Интерфейс настраивается через файл. Цвета переопределяют переменные CSS во время выполнения, поэтому смена темы клиента ничего не перекомпилирует.

Файл#

Скопируйте brand.example.yaml в brand.yaml в корне или укажите на него BREVIS_BRAND_FILE:

yaml
titulo: Acme Data
subtitulo: Data platform

frase: |
  Measure before deciding.
  Decide before scaling.

cores:
  fundo:    "#f4efe4"
  tinta:    "#21180f"
  destaque: "#aa8450"

Каждое поле необязательно. То, что вы опустите, сохраняет значение по умолчанию, поэтому файл с одним лишь titulo: уже валиден.

Перенос строки в frase сохраняется: он задаёт ритм фразы в боковой панели.

Логотип#

yaml
logo: https://example.com/mark.svg

Принимает URL (https:// или http://) или внутренний путь, начинающийся с /. Если не указан, используется встроенный символ, который следует цвету темы.

Логотип, размещённый на стороне, зависит от этого хоста

Если хост недоступен или у кластера нет исходящего доступа в интернет, изображение не загрузится. Остальная часть интерфейса продолжит работать, но учитывайте это при выборе: остальной UI, включая шрифты и бандлы, отдаётся из самого бинарного файла именно для того, чтобы не зависеть от сети.

Проверка#

Неверное шестнадцатеричное значение проявилось бы только при запуске контейнера, а сообщение пришло бы через журнал pod — далеко от того, кто редактировал файл. Поэтому есть подкоманда:

bash
brevis marca brand.yaml
  ok    Acme Data · Data platform
        logo      /assets/logo.svg  (built-in symbol)
        accent    (the product's own)
        Powered by Brevis

Вызывайте её в CI установки, и ошибка вернётся в pull request.

Отсутствие означает разное

В serve отсутствующий файл означает «использовать идентичность по умолчанию» — и API поднимается. В marca отсутствующий файл — это ошибка: тот, кто попросил проверить путь, ожидает, что ему скажут, что такого пути нет.

Поведение при старте#

Ошибка в содержимом — недопустимый цвет, сломанный YAML — не мешает интерфейсу подняться. Процесс записывает предупреждение и использует тему по умолчанию. Положить API из-за цвета было бы хуже, чем отдавать его с темой по умолчанию.

level=WARN msg="visual identity ignored" file=brand.yaml error="brand.yaml: colour accent: \"#gggggg\" is not a hex value (#rgb, #rrggbb or #rrggbbaa)"

Что нельзя настроить#

Строка «Powered by Brevis» в подвале не берётся из конфигурации — она берётся из кода.

В Kubernetes#

Смонтируйте файл из ConfigMap:

yaml
volumes:
  - name: brand
    configMap: {name: brevis-brand}
containers:
  - name: api
    volumeMounts:
      - {name: brand, mountPath: /etc/brevis}
    env:
      - name: BREVIS_BRAND_FILE
        value: /etc/brevis/brand.yaml
