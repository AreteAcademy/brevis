Контекст между шагами

Что один шаг сообщает следующему — две переменные окружения и файл.

Шаг публикует значения; шаги, которые от него зависят, их читают. Это всё, что делает эта функциональность.

yaml
steps:
  - id: extract
    run: python fetch.py

  - id: transform
    run: python transform.py
    depends_on: [extract]
python
# extract
from brevis import context
context.set(bucket="s3://landing/2026-09-07", rows=48213)
python
# transform
from brevis import context
bucket = context.get("extract.bucket")

Ключ всегда имеет вид <step id>.<name>. Шаг читает то, что опубликовали его собственные зависимости, и ничего больше.

Чем это не является

Это не очередь сообщений, не состояние между запусками и не место для данных. Это записка, которую один шаг оставляет следующему: путь, водяной знак, счётчик.

Любой язык, библиотека не требуется#

Контракт — это две переменные окружения и файл, поэтому участвовать может шаг вообще без SDK:

bash
window=$(jq -r '.extract.watermark' <<< "$BREVIS_INPUT")
./publish --until "$window"
jq -n --arg n "$(date -Is)" '{published_at: $n}' > "$BREVIS_OUTPUT"
BREVIS_INPUT{"<step id>": {…}} — что опубликовали зависимости этого шага
BREVIS_OUTPUTпуть, по которому нужно записать один JSON-объект

В Kubernetes этот путь — /dev/termination-log, который engine и так читает, чтобы получить код завершения. Поэтому ни вызова API, ни токена, ни порта не нужно, а библиотека для этого — это разбор JSON и запись файла.

язык
Pythonpip install brevis — в нём есть и brevis.run с автоматическими параметрами
Gosdk/context, часть модуля SDK, ни от чего не зависит
любой другойдве переменные выше

Изоляция#

Ни один шаг не может перезаписать то, что опубликовал другой. Ключи получают префикс с id того, кто их записал, и этот префикс определяет engine, а не шаг. Два шага, публикующие bucket, дают extract.bucket и load.bucket, и ни один не пропадает.

Потолок в 4096 байт#

То, что публикует шаг, должно умещаться в 4096 байт. Предел не произвольный: в Kubernetes транспортом служит /dev/termination-log, а столько принимает kubelet.

Превышение — это ошибка шага, в сообщении указано, сколько байт было записано. Альтернативой было бы усечение, а усечённый JSON — невалидный JSON, который обнаружит следующий шаг, не имея возможности понять, что ошибка не в нём.

Если значение не умещается, это не контекст: запишите его в бакет и опубликуйте путь.

Повторные попытки и возобновлённые запуски#

При новой попытке шаг публикует снова, и предыдущее значение заменяется. Шаг, который уже завершился успешно, не выполняется и не публикует повторно — то, что он сообщил, остаётся в силе для зависящих от него шагов.

Запуск шага вручную#

Две переменные — это весь контракт, поэтому воспроизвести запуск — значит экспортировать их:

bash
export BREVIS_INPUT='{"extract":{"bucket":"s3://landing/2026-09-07"}}'
export BREVIS_OUTPUT=/tmp/out.json
python transform.py
cat /tmp/out.json
