Документация

Console

Веб-интерфейс Core: что выполняется, что будет выполняться и что произошло с каждым запуском.

Интерфейс поставляется внутри бинарного файла — это не отдельный сервис, который нужно устанавливать и поддерживать. Доля успешных запусков, средняя длительность, очередь, история попыток и расписание ближайших запусков.

Console поднимается вместе с brevis serve на том же порту, что и HTTP API (BREVIS_HTTP_ADDR, по умолчанию :8080). В Быстром старте он открывается по адресу localhost:8080.

Экраны ниже воссозданы в SVG по консоли, с демонстрационными данными, — никогда не скриншоты: настоящая консоль работает с данными клиентов в продакшене.

Обзор#

Обзор с метриками и графиками. Доля успешных запусков, средняя длительность, то, что выполняется сейчас, и ближайшие запланированные запуски — на одном экране.

Workflows#

Список workflow с поиском, фильтрами, паузой и запуском. В каждой строке указаны cron, следующий и последний запуск и теги.

Один workflow#

Шаги и зависимости, форма запуска с параметрами, DAG с состоянием каждого шага и календарь на год, где каждый день окрашен в цвет худшего результата.

Запуски#

История запусков с попыткой каждого. Состояние, workflow, триггер, слот, к которому относится запуск, длительность и время создания.

Один запуск#

DAG запуска в реальном времени и авто-параметры, которые engine вычислил для него. Граф с командой, образом и длительностью каждого шага и вывод каждого шага.

Проекты#

Проекты, чтобы две команды не конфликтовали из-за одного имени. Каждый проект задаёт пространство имён для своих workflow: у двух проектов может быть по daily_ingest.

Поставляется в бинарном файле#

Шрифты и бандлы отдаются из бинарного файла — работает без интернета.
