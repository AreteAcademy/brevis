Рантайм шага

Что шаг объявляет о языке и инструментах, которыми он управляет, и почему делать это нужно редко.

На графе у каждого шага рисуется метка с его языком и инструментами, которыми он управляет:

┌──────────────────────────────────────┐
│ ● transform            SDK v0.57.0   │
│   dbt build --select gold            │
│   ⬤ Python  ▢ dbt                    │
│   2m14s · attempt 1                  │
└──────────────────────────────────────┘

В большинстве случаев писать ничего не нужно. Engine читает run: и image: и определяет всё сам.

Когда это объявлять#

Два поля, оба необязательные, оба на уровне шага:

yaml
steps:
  - id: fetch
    run: /opt/brevis/bin/fetch-weather
    runtime: go            # a compiled binary; the path says nothing

  - id: transform
    run: dbt build --select gold+
    tools: [dbt]           # what it drives, not what it is
поле
runtimeязык шага: go, python, node, shell…
toolsинструменты, которыми управляет команда: dbt, dlt, spark…

Практическое правило: объявляйте, когда вывод ошибается. run:, указывающий на скомпилированный бинарный файл, не может сказать, что это Go; обёртка, внутри вызывающая dbt, не может сказать, что управляет dbt.

Почему словарь закрыт#

Идентификатор вне словаря отклоняется при публикации с перечнем допустимых. Альтернатива — метка, которая через три дня отрисуется пустой на экране, и проследить причину будет не за что.

workflow "daily": step "transform": `runtime: pyton` is not valid
  (valid: go, python, node, shell, …)

Зачем нужна метка#

Это не украшение. Когда запуск падает в три часа ночи, первый вопрос — «что выполняет этот шаг?», а ответ обычно лежит в другом репозитории. Метка выносит его на сам граф — рядом с версией SDK, которую использовал шаг, а она отличает «сломалось сегодня» от «сломалось со вторничного обновления».

Дальнейшие шаги#

  • Workflows — все поля шага
  • Pod на шаг — где на самом деле выполняется шаг
  • Наблюдаемость — сопутствующие метрики
