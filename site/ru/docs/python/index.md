# Python

> pip install brevis — контекст между шагами, часы запуска и собственные метрики вашего пайплайна, совсем без зависимостей.

*https://brevis.sh/ru/docs/python/ · brevis.sh docs (ru)*

---

```bash
pip install brevis
```

```python
from brevis import context, metrics, run

bucket = context.get("extract.bucket")
since, until = run.window()          # the window this run covers

context.set(rows=48213, watermark="2026-09-07T03:00:00Z")
metrics.set("rows_loaded", 48213)    # reaches the engine's /metrics
```

**Никаких зависимостей, никогда.** Она читает одну переменную окружения,
записывает один файл и выводит одну строку в stdout. Требуется Python 3.9+.

Это не порт Go SDK: нет драйверов, нет пагинации, нет ingestion id. Она
существует, чтобы команда могла использовать pandas, Polars или dbt и всё же
получать то, для чего нужен оркестратор.

## Чтение контекста

Ключ всегда квалифицирован шагом, который его опубликовал:

```python
context.get("extract.bucket")            # the value
context.get("extract.nope", default=0)   # absent is not an error
context.of("extract")                    # everything that step published
context.published()                      # what THIS step has published so far
```

`context.get("bucket")` без шага **отклоняется** с перечислением шагов,
опубликовавших такой ключ. Шаги изолированы — `extract` и `transform` могут
оба опубликовать `bucket`, и ни один не потеряет его, — а ключ без шага
перечёркивает это в тот момент, когда их становится два. Поиск и выбор одного —
это приоритет по случайности: работает, пока молча не перестаёт.

Чтение шага, от которого этот не зависит, — ошибка, и сообщение указывает на
исправление.

## Запись

```python
context.set(name="Daniel")
context.set(label="Name")
# both survive: {"name": "Daniel", "label": "Name"}
```

Вызовы **объединяются**. Один и тот же ключ дважды сохраняет последнюю запись;
другой ключ не затрагивает первый. **Аргумента шага нет** — единственное
пространство имён, в которое процесс может писать, — его собственное, и именно
это делает изоляцию структурной, а не правилом.

Ничто не попадает на диск до завершения процесса, поэтому жёстко упавший шаг
ничего не публикует. Это правильно: вывод упавшего шага описывал бы
незавершённую работу.

## Часы, которые должен читать этот запуск

Каждый запуск также несёт **авто-параметры**: значения, которые engine
вычисляет сам. Их никто не объявляет, они есть у каждого запуска, и они
отвечают на вопрос, на который пайплайн иначе ответил бы с помощью
`datetime.now()`.

```python
from datetime import timedelta
from brevis import run

since, until = run.window() or (run.now() - timedelta(days=1), run.now())
df = fetch(since, until)
df.to_parquet(f"/data/{run.auto().date}.parquet")
```

:::warning Почему не `datetime.now()`
`run.now()` — это **слот** запуска по расписанию. Загрузчик, который читает
`datetime.now()` и вычитает два часа, прав на запуске, начавшемся вовремя, и
неправ на сорок минут на том, который очередь задержала, — а эти сорок минут
принадлежат **ни одному запуску**, потому что следующий слот тоже читает
собственный `now()`. Ничего не падает, а пробел обнаруживается спустя недели.
:::

| | |
|---|---|
| `run.now()` | часы: слот или момент старта запуска |
| `run.window()` | `(start, end)`, конец исключён — или `None` |
| `run.auto()` | авто-параметры, см. ниже |
| `run.context()` | id, попытка, триггер, параметры и auto |
| `run.params()` · `run.param(name)` | параметры, объявленные в workflow |
| `run.map_index()` · `run.map_value()` | экземпляр, при `for_each:` |

`window()` определяется **cron**, а не историей: backfill слота из марта даёт
окно, которое было в марте. Запрос `[start, end)` никогда не пересекается и не
оставляет пробелов, как бы поздно ни шёл запуск и как бы часто он ни
повторялся.

Если у workflow нет расписания, возвращается `None`, а не пара нулевых значений
времени: запрос с начала эпохи выбирает всё, и такой сбой не должен быть
тихим. `or` выше — это весь запасной вариант.

### Авто-параметры

| поле | |
|---|---|
| `date` | `"2026-09-08"` — партиция, папка, `WHERE` |
| `adjusted_at` | часы, которые нужно читать вместо `now()` |
| `scheduled_at` | слот, который запросил cron; `None` при ручном запуске |
| `started_at` | когда началась **эта попытка**; повторная попытка сдвигает его |
| `delay_seconds` | насколько эта попытка опоздала; никогда не отрицательно |
| `interval_start` · `interval_end` | окно, конец исключён |
| `previous_error` | предыдущий запуск не завершился успешно |
| `previous_success_at` | слот последнего запуска, который **завершился успешно** — то, что делает `previous_error` применимым на практике |

Запустите скрипт вручную, и `run.now()` — это **настенные** часы, а `window()`
— `None`, поэтому для локальной разработки не нужно писать никакой ветки.

## Один экземпляр размноженного шага

При [`for_each:`](/ru/docs/workflows/index.md) engine запускает по одному процессу на
элемент и сообщает каждому, какой элемент он получил:

```python
partition = run.map_value()
if partition is None:
    raise SystemExit("this step is meant to run under `for_each:`")

load(f"/data/{partition}.csv")
```

JSON-строка приходит **без кавычек** — `for_each` по `["2026-01"]` передаёт
шагу `2026-01`, а не `"2026-01"`. Всё остальное — объект, число, список —
приходит как свой JSON, поэтому `json.loads(run.map_value())`.

Оба значения — `None` у шага, который не размножен. Именно `None`, а не `-1`
или `""`: сентинел — это число, с которым кто-нибудь в конце концов начнёт
делать арифметику, а пустая строка неотличима от элемента, который *является*
пустой строкой.

Размноженный шаг **не публикует контекст** вниз по графу — четыре экземпляра
не могут делить один ключ. Шаг, которому нужно что-то передать дальше, пишет
файл, либо следующий за ним шаг считает приземлившееся.

## Метрики, которые знает только ваш пайплайн

Engine уже измеряет то, что видит: длительность, попытки, глубину очереди. Чего
он знать не может — сколько строк приземлилось, сколько отклонил вендор или
сколько байт было отброшено. Это знает шаг, а библиотека это передаёт.

```python
from brevis import metrics

metrics.set("rows_loaded", 48213)          # a gauge: the last value wins
metrics.inc("vendor_rejected_total")       # a counter: it adds up
metrics.inc("bytes_discarded_total", 4096)
```

Они появляются в `/metrics` **engine**, на порту планировщика, с метками
workflow и шага:

```
brevis_step_rows_loaded{workflow="daily_sales",step="load"} 48213
brevis_step_vendor_rejected_total{workflow="daily_sales",step="load"} 5
```

| | |
|---|---|
| `metrics.set(name, value)` | gauge. После завершения шага значение остаётся, пока следующий запуск не запишет другое |
| `metrics.inc(name, by=1)` | счётчик. Суммируется по шагам и по запускам |

### Почему это не открывает порт

Потому что **шаг нельзя опросить**. `:9090` принадлежит планировщику и API —
долгоживущим процессам со стабильным адресом, которые опрашивают раз в
пятнадцать-шестьдесят секунд. Шаг стартует в своём pod, работает сорок секунд и
завершается: открытый им порт был бы опрошен ни разу или один раз по везению.

Три известных ответа на это — Pushgateway (компонент, который нужно
обслуживать, и серии, остающиеся, пока кто-нибудь их не удалит), коллектор OTLP
(компонент **и** зависимость в этой библиотеке, у которой их нет и не будет)
или поручить передачу **оркестратору**. Brevis уже читает stdout каждого шага в
поисках строк `@brevis:` — так фазы SDK попадают на граф — и у него уже есть
измеритель и endpoint Prometheus.

Поэтому библиотека пишет **одну строку в stdout**, а остальное делает engine.
Метрика приходит с метками workflow и шага бесплатно, потому что engine знает,
что он запускал; через Pushgateway этой библиотеке пришлось бы размечать себя
самой, и она бы ошиблась.

Запись выполняется через `print(flush=True)`, потому что engine читает этот
канал **вживую**. Буферизованная строка приходит при завершении процесса — для
шага, работающего час, это опоздание на час, а для убитого шага — никогда.

### Что метрика отклоняет

**Недопустимое имя отклоняется громко.** Prometheus принимает буквы, цифры и
подчёркивание, и первый символ не может быть цифрой. Отвергнутое им имя не
порождает сломанную метрику — оно порождает вывод, который он **отказывается
разбирать**, и теряется **весь сбор**, а с ним и все остальные метрики. Поэтому
`rows-loaded` вызывает здесь `MetricError`, там, где допущена ошибка, а не
приходит под именем, которого никто не писал.

| отклоняется | потому что |
|---|---|
| `rows-loaded`, `rows loaded`, `2rows` | Prometheus это не разберёт, и теряется весь сбор |
| `metrics.set("ok", True)` | `bool` в Python — это `int`, а сообщение `1` — число, смысл которого зависит от знания этого. Сообщайте количество или длительность, а не состояние |
| `metrics.inc("x", -1)` | счётчик только растёт. Каждый `rate()` над ним исходит из этого, и поломка проявляется на графике спустя недели |

Запустите скрипт вручную, и строка всё равно уходит в stdout, где читается как
то, что она есть. Ничто её не собирает, и ничего не падает — так же, как
`context.set()` на ноутбуке.

## Что она отклоняет

| | потому что |
|---|---|
| больше 4096 байт | платформа **усекает**, а не отклоняет, поэтому слишком большой объект приходит обрезанным вдвое и ниже по графу читается как «ничего не опубликовано» |
| значение не в формате JSON | `datetime` превращается в `"..."` или исчезает в зависимости от того, кто сериализует. Ошибка называет ключ и предлагает `.isoformat()` |
| нестроковый ключ | `{1: "x"}` возвращается как `{"1": "x"}`, и поиск промахивается |

Потолок — число платформы, а не наше. Любая функция «контекст между задачами»
ломается одинаково: кто-то кладёт **данные** туда, где подходит только
**контекст**. В четыре килобайта помещаются водяной знак, счётчик или список
партиций. Публикуйте ссылку, а строки оставляйте на месте.

:::danger Это не хранилище секретов
Всё опубликованное видно любому, кто видит запуск, — оно находится в статусе
pod и в истории запусков. Публикуйте путь, а не подписанный URL.
:::

## Запуск вручную

Вне Brevis нет входа, и никто не читает вывод. `get()` возвращает значение по
умолчанию, `set()` принимает и отбрасывает, а библиотека один раз сообщает об
этом на уровне INFO. Она **не вызывает исключений**: скрипт, который нельзя
запустить вручную, нельзя разрабатывать. Валидация всё равно выполняется,
поэтому значение, работающее на вашем ноутбуке, работает и в продакшене.

## Тестирование вашего шага

Весь контракт — две переменные окружения, поэтому мокать нечего:

```python
def test_my_step(monkeypatch, tmp_path):
    monkeypatch.setenv("BREVIS_INPUT", '{"extract": {"rows": 42}}')
    monkeypatch.setenv("BREVIS_OUTPUT", str(tmp_path / "out"))
    assert context.get("extract.rows") == 42
```

## Версии

Библиотека версионируется сама по себе, отдельно от engine и от Go SDK.

:::warning Не используйте `0.2.0`
Она вышла на PyPI только в виде wheel. `0.2.1` — тот же код, но полный.
:::

`brevis.run` нужен engine версии **`v0.9.0` или новее**, чтобы было что читать;
на более старом все поля пусты, а `run.now()` — это настенные часы, то есть то
же, что и вне engine.
