文档

安装、理解和运维 brevis.sh 所需的一切 — 从第一个 workflow 到 Kubernetes 部署。

入门

生态

brevis.sh 的四个组成部分、各自的职责，以及数据经过的路径。

集成

什么与什么相连：数据从哪里来，落到哪里，在哪里建模，以及这一切在哪里运行。

简介

brevis.sh 是什么，它解决什么问题，以及它在什么情况下不是合适的选择。

安装

如何获取二进制文件、它有哪些要求，以及如何确认安装正确。

快速开始

从零开始，四步在界面中看到一个运行中的 DAG。

概念

Core

编排器：调度 run，把队列保存在 Postgres 中，并为每个 step 启动一个 pod，从不接触数据。

Workflows

完整的 YAML 格式：step、依赖、镜像、资源和调度。

调度器与队列

两个相互独立的循环：谁创建 run，谁执行 run，以及为什么要把它们分开。

每个 step 一个 pod

为什么每个 step 都在自己的 pod 中运行，以及这在成本和隔离方面带来了什么变化。

step 之间的上下文

一个 step 告诉下一个 step 什么：两个环境变量和一个文件。

参考

CLI

引擎的十二个子命令，包括标志、参数以及每个命令的前提条件。

参数

同一个 workflow 的两次 run 之间可以变化的内容，无需编辑文件。

配置

所有环境变量，包括默认值、格式，以及缺失时会发生什么。

step 运行时

step 对其使用的语言和驱动的工具做了什么声明，以及为什么你很少需要声明。

SDK 与库

Go SDK

编写抓取器：从源中抽取、转换，并加载到目的地。

客户端库

任何语言的 step 如何读取上下文和 run 的时钟，以及哪些语言已经有了库。

Python

pip install brevis：step 之间的上下文、run 的时钟，以及你的 pipeline 自己的指标，完全没有依赖。

运维

Console

Core 的 Web 界面：什么正在运行，什么即将运行，以及每个 run 发生了什么。

Kubernetes

如何部署引擎、需要哪些权限，以及部署之后应该检查什么。

可观测性

两个进程的 Prometheus 指标、应该关注什么，以及刻意缺失的内容。

白标

通过一个 YAML 文件修改界面的标题、格言、logo 和配色。

摄取

摄取

一个落地数据的 HTTP 端点：校验、标识、分批、投递。有自己的镜像，有自己的版本。

摄取 sink

六个目的地、各数据库如何写入一条记录，以及为什么镜像只包含你用到的部分。

基准测试

我们如何度量 gateway、数字说明了什么，以及必须一致的三个见证。

用 SQL 建模

SQL

普通的 .sql 文件按依赖顺序变成表和视图，既可作为 workflow 的 step，也可独立使用。
