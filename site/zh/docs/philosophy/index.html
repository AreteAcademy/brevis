理念

brevis.sh 的来历：塞内卡、Aretê Academy，以及这些在代码中决定了什么。

brevis.sh 诞生于 Aretê Academy 内部：把纪律、目标和卓越应用于构建软件。

De brevitate vitae#

不是我们的时间太少，而是我们浪费了太多。

塞内卡的这句格言引导着 brevis.sh 背后的那个问题：哪些复杂性真正值得团队投入时间？每个 workflow 都在隔离的 pod 中运行，使失败、版本和依赖都有清晰的边界。

运行时中的四个选择由此而来：

  • 每个 step 一个镜像：每个 step 声明自己需要的运行时。升级一个版本，不会迫使你去动其他的。
  • 按 run 保存日志：输出属于产生它的 run。调查失败，不必重建丢失的上下文。
  • 持久化的重试：尝试的生命周期超过进程。重启不会抹去已经掌握的关于这项工作的信息。
  • 依赖隔离：一个 step 携带的东西不会泄漏给它的邻居。清晰的边界让失败变得可读。

项目的主张#

介于*没有实践的哲学*与*没有方向的技术*之间，是去做真正重要之事的清晰。

工具塑造我们的思考方式。#

“可持续的代码，不仅是能一直运行的代码。它是为人们留出思考空间的代码。”：应用于软件的哲学

“清晰并不与精深相对立。它是防止精深沦为噪音的标准。”：原则性的开源
