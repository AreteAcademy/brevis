Open Source · In Go gebaut · Self-hosted

Von Rohdaten zu modellierten Tabellen. In Go.

Orchestrierung, Extraktion, Ingestion und Datenmodellierung — Core, SDK, Gateway und SQL — vereint in Go. Open Source, in Ihrem Cluster, ohne dass Daten durch den Orchestrator laufen.

betreiben Sie es, wie Sie möchten

Auf Ihrem Rechner, in Ihrem Cluster oder auf einer Runtime, die Sie bereits betreiben.

Open Source und self-hosted: dasselbe Binary an allen drei Orten. Kein Dienst von uns dazwischen.

Docker Compose empfohlen

Postgres, Core, Konsole und Gateway auf einem Rechner, zum Ausprobieren oder Entwickeln.

$ git clone https://github.com/AreteAcademy/brevis
$ cd brevis && docker compose up
So geht's

Kubernetes + Helm

Das Chart im Repository: Migrationen als Hook, ein Image pro Rolle und minimales RBAC für die Step-Pods.

$ helm install brevis ./deployments/helm/brevis \
    --namespace data --create-namespace \
    --set database.url="postgres://…" \
    --set auth.user=admin \
    --set auth.passwordHash="$(brevis hash)" \
    --set auth.secret="$(openssl rand -base64 48)"
So geht's

Ihre eigene Runtime

Ein Step mit host: geht an einen Agent, den Sie betreiben — dort, wo die Lizenz, die GPU oder die freigegebene IP liegt.

# im Workflow-Step
host: tools

$ kubectl apply -f deployments/kubernetes/agent.yaml
So geht's
