Core

hello.yaml
name: hello
type: dag
tags: [example]

steps:
  - id: prepare
    run: sh -c 'echo preparing; sleep 1'

  # The next two depend on the same step, so they run IN PARALLEL.
  - id: extract
    run: sh -c 'sleep 2; echo 42 extracted'
    depends_on: [prepare]

  - id: validate
    run: sh -c 'sleep 1; echo validated'
    depends_on: [prepare]

  - id: publish
    run: echo published
    depends_on: [extract, validate]
shell
$ docker run --rm -v ./hello.yaml:/w/hello.yaml -w /w \

SDK

shell
$ go get github.com/AreteAcademy/brevis/sdk@latest
main.go
rows, err := sdk.Extract(ctx, sdk.Source{
	From: from.HTTP{URL: "https://api.example.com/v1/events"},
})

rows = sdk.Transform(rows, sdk.Accept("id", "created_at", "amount"))

res, err := sdk.Load(ctx, rows, sdk.Target{
	To:      bigquery.Table{Dataset: "bronze", Name: "events"},
	Columns: []string{"id", "created_at", "amount"},
})

Requer Go 1.23 ou mais novo.

Gateway

gateway.yaml
name: events_gateway

listen:
  addr: :8080
  auth:
    type: bearer
    keys_from: BREVIS_INGEST_KEYS

streams:
  - name: clicks
    path: /v1/clicks
    format: json
    identity:
      provider: web
      entity: click
      source_key: event_id
      record_ts: occurred_at
    sink:
      type: files
      path: /var/landed/
    dead_letter:
      type: files
      path: /var/landed/dead-letter/
shell
$ docker run -p 8080:8080 -e BREVIS_INGEST_KEYS=dev-key \
  -v ./gateway.yaml:/etc/brevis/gateway.yaml:ro -v ./landed:/var/landed \
  areteacademy/brevis-gateway:0.26.1-slim

$ curl -X POST localhost:8080/v1/clicks -H 'Authorization: Bearer dev-key' \
  -d '{"event_id":"e-1","occurred_at":"2026-10-08T12:00:00Z","page":"/pricing"}'
{"accepted":1,"rejected":null}  202

SQL

models/staging/stg_orders.sql
/* brevis
materialized: view
*/
select order_id, customer_id, amount, ordered_at
from raw.orders
where amount is not null
models/marts/orders.sql
/* brevis
materialized: table
tests:
  - not_null: [customer_id]
  - unique: [customer_id]
*/
select customer_id, count(*) as orders, sum(amount) as revenue
from staging.stg_orders
group by customer_id

arquitetura

Quatro peças. O dado passa por três.

O Core agenda, enfileira e observa — e nunca toca o dado. Quem toca é o SDK, que busca; o Gateway, que recebe; e o SQL, que modela onde o dado já pousou.

implante do seu jeito

Na sua máquina, no seu cluster, ou num runtime que já é seu.

Open source e self-hosted: o mesmo binário nos três lugares. Não há serviço nosso no meio.

Docker Compose recomendado

Postgres, Core, console e Gateway numa máquina, para conhecer ou desenvolver.

$ git clone https://github.com/AreteAcademy/brevis
$ cd brevis && docker compose up
Como fazer

Kubernetes + Helm

O chart do repositório: migrações como hook, uma imagem por papel e RBAC mínimo para os pods de etapa.

$ helm install brevis ./deployments/helm/brevis \
    --namespace data --create-namespace \
    --set database.url="postgres://…" \
    --set auth.user=admin \
    --set auth.passwordHash="$(brevis hash)" \
    --set auth.secret="$(openssl rand -base64 48)"
Como fazer

O seu runtime

Uma etapa com host: vai para um agent que você mantém — onde mora a licença, o GPU ou o IP liberado.

# na etapa do workflow
host: tools

$ kubectl apply -f deployments/kubernetes/agent.yaml
