# 哲学

> brevis.sh の由来 — セネカ、Aretê Academy、そしてそれがコードの中で何を決めているか。

---

brevis.sh は Aretê Academy の中から生まれました。規律、目的、卓越性を、ソフトウェアの構築に適用したものです。

## De brevitate vitae

> 私たちに時間が少ないのではない。多くを失っているのだ。

セネカのこの格言が、brevis.sh の背後にある問いを導いています。どの複雑さが、本当にチームの時間に値するのか。
すべてのワークフローは分離された pod で動くので、失敗、バージョン、依存関係に明確な境界があります。

その問いから、ランタイムにおける 4 つの選択が生まれました。

- **ステップごとのイメージ** — 各ステップが必要なランタイムを宣言します。1 つのバージョンを上げても、他のステップに手を入れる必要はありません。
- **run ごとのログ** — 出力は、それを生んだ run に属します。失敗の調査は、失われた文脈の再構築ではありません。
- **永続的なリトライ** — 試行はプロセスより長く生きます。再起動しても、その仕事についてすでにわかっていたことは消えません。
- **依存関係の分離** — あるステップが抱えるものが、隣のステップに漏れることはありません。明確な境界が、失敗を読み取れるものにします。

## プロジェクトが提案するもの

*実践のない哲学*と*方向のない技術*のあいだで、**重要なことをするための明晰さ。**

## 道具は、私たちの考え方を形作る。

> 「持続可能なコードとは、動き続けるだけのコードではない。人が考える余地を残すコードである。」 — ソフトウェアに応用された哲学

> 「明晰さは、洗練の反対ではない。洗練がノイズになるのを防ぐ基準である。」 — 原則としてのオープンソース
