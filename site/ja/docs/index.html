ドキュメント

brevis.sh のインストール、理解、運用に必要なすべて — 最初の workflow から Kubernetes へのデプロイまで。

はじめに

エコシステム

brevis.sh の 4 つの構成要素と、それぞれの役割、そしてデータが通る場所。

インテグレーション

何が何につながるか。データの取得元、着地先、モデリングの場所、そして全体が動く場所。

はじめに

brevis.sh とは何か、何を解決するのか、そしてどんなときに最適な選択ではないのか。

インストール

バイナリの入手方法、必要なもの、そしてインストールが正しいことの確認方法。

クイックスタート

何もない状態から、インターフェース上で動く DAG まで、4 つのステップで。

基本概念

Core

オーケストレータ。run をスケジュールし、キューを Postgres に保持し、ステップごとに 1 つの pod を起動します。データには一切触れません。

Workflows

YAML 形式の全体 — ステップ、依存関係、イメージ、リソース、スケジュール。

スケジューラとキュー

2 つの独立したループ — 誰が run を作り、誰が実行するのか、そしてなぜ分かれているのか。

ステップごとの pod

なぜ各ステップが専用の pod で動くのか、そしてそれがコストと分離にどう影響するのか。

ステップ間のコンテキスト

あるステップが次のステップに伝えるもの — 2 つの環境変数と 1 つのファイル。

リファレンス

CLI

エンジンの 12 個のサブコマンドと、そのフラグ、引数、それぞれが必要とするもの。

パラメータ

ファイルを編集せずに、同じワークフローの 2 回の run の間で変えられるもの。

設定

すべての環境変数について、デフォルト、形式、未設定の場合に何が起きるか。

ステップのランタイム

ステップが、使う言語と操作するツールについて宣言するもの — そして、ほとんど宣言が要らない理由。

SDK とライブラリ

Go SDK

フェッチャーの書き方 — ソースから抽出し、変換し、宛先にロードします。

クライアントライブラリ

どの言語のステップでも、コンテキストと run の時計を読み取る方法、そしてすでにライブラリがある言語。

Python

pip install brevis — ステップ間のコンテキスト、run の時計、パイプライン独自のメトリクスを、依存関係ゼロで。

運用

Console

Core の Web インターフェース。何が動いていて、何が実行される予定で、各 run に何が起きたか。

Kubernetes

エンジンのデプロイ方法、必要な権限、そしてデプロイ後に確認すること。

オブザーバビリティ

両方のプロセスの Prometheus メトリクス、何を監視するか、そして意図的に存在しないもの。

ホワイトラベル

1 つの YAML ファイルで、インターフェースのタイトル、モットー、ロゴ、パレットを変更します。

取り込み

取り込み

データを着地させる HTTP エンドポイント — 検証、識別、バッチ化、配信。専用のイメージ、専用のバージョン。

取り込みの sink

6 つの宛先、各データベースがレコードを書き込む方法、そしてイメージが使うものだけを含む理由。

ベンチマーク

gateway の測り方、数字が示すこと、そして一致していなければならない 3 つの証人。

SQL によるモデリング

SQL

通常の .sql ファイルを、依存関係の順にテーブルとビューへ変換します — ワークフローのステップとして、または単独で。
