ドキュメント

Core

オーケストレータ。run をスケジュールし、キューを Postgres に保持し、ステップごとに 1 つの pod を起動します。データには一切触れません。

ワークフロー全体が 1 つのバージョン管理されたファイルです。パイプラインのレビューは差分のレビューになります。Core はスケジュールし、キューに積み、各ステップを専用のイメージで起動しますが、データには一切触れません。

何をするか#

  • スケジュールする。 スケジューラは各ワークフローのスケジュールを読み、run を作成します。スケジューラとキューは 2 つの独立したループで、片方が詰まってももう片方は止まりません — スケジューラとキュー。
  • キューに積む。 キューは Postgres にあります。実行する側が保留中の run を取得し、グラフをたどり、各ステップの状態を記録します。
  • ステップごとに 1 つの pod を起動する。それぞれ専用のイメージを使います — ステップごとの pod。
  • データには一切触れない。 Core から出るのは制御の線だけです。データを読み書きするのはステップであり、SDK か、あなた自身のコードを使います。

1 つのワークフローを端から端まで#

ワークフローは 1 つの YAML ファイルです。同じステップに依存する 2 つのステップは並列に実行されます。

yaml
name: hello
type: dag
tags: [example]

steps:
  - id: prepare
    run: sh -c 'echo preparing; sleep 1'

  # The next two depend on the same step, so they run IN PARALLEL.
  - id: extract
    run: sh -c 'sleep 2; echo 42 extracted'
    depends_on: [prepare]

  - id: validate
    run: sh -c 'sleep 1; echo validated'
    depends_on: [prepare]

  - id: publish
    run: echo published
    depends_on: [extract, validate]

キューもクラスタもなしでローカルに実行するには:

bash
docker run --rm -v ./hello.yaml:/w/hello.yaml -w /w \
  brevissh/brevis:0.40.0-worker run hello.yaml

出力:

text
workflow hello (dag, 4 steps) in .
  ▶ prepare
    prepare | preparing
  ✓ prepare
  ▶ validate
  ▶ extract
    validate | validated
  ✓ validate
    extract | 42 extracted
  ✓ extract
  ▶ publish
    publish | published
  ✓ publish

workflow hello finished

公開済みのイメージで得た実際の出力です。brevis run はキューなしでローカルに実行します。pod を起動するのはスケジューラです。
