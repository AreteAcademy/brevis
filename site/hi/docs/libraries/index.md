# क्लाइंट लाइब्रेरी

> किसी भी भाषा का step संदर्भ और run की घड़ी कैसे पढ़ता है — और किन भाषाओं की लाइब्रेरी पहले से है।

*https://brevis.sh/hi/docs/libraries/ · brevis.sh docs (hi)*

---

Step को ऑर्केस्ट्रेटर से दो चीज़ें चाहिए: **पिछले step ने क्या प्रकाशित किया** और **यह run कौन-सी घड़ी
पढ़े**। क्लाइंट लाइब्रेरी बस यही दो सौंपती हैं, और कुछ नहीं।

## अनुबंध लाइब्रेरी से पहले आता है

Engine जो परिभाषित करता है वह **दो environment वेरिएबल और एक फ़ाइल** है:

| | |
|---|---|
| `BREVIS_INPUT` | `{"<step id>": {…}}` — इस step की निर्भरताओं ने जो प्रकाशित किया |
| `BREVIS_OUTPUT` | उस path का नाम जिस पर **एक** JSON ऑब्जेक्ट लिखना है |

साथ में run के वेरिएबल और auto पैरामीटर, सब केवल-पढ़ने के लिए: `BREVIS_RUN_*` और `BREVIS_AUTO_*`।
Kubernetes के तहत `BREVIS_OUTPUT` `/dev/termination-log` है, जिसे engine exit code पाने के लिए पहले से पढ़ता है।

इसलिए **कोई API कॉल, कोई token और कोई port नहीं**। किसी भी भाषा का step एक JSON parse और एक फ़ाइल write से
हिस्सा लेता है:

```bash
window=$(jq -r '.extract.watermark' <<< "$BREVIS_INPUT")
./publish --until "$window"
jq -n --arg n "$(date -Is)" '{published_at: $n}' > "$BREVIS_OUTPUT"
```

यहाँ लाइब्रेरी कोई नई क्षमता नहीं खोलती — वह आपको validation, अनुपस्थित मान की सँभाल और त्रुटि संदेश
बचा देती है, जिन्हें दोबारा न लिखना ही बेहतर है।

## कौन-कौन-सी मौजूद हैं

| भाषा | | |
|---|---|---|
| **Python** | `pip install brevis` | [उपलब्ध](/hi/docs/python/index.md) — PyPI पर `0.2.1` |
| **Go** | `brevis/sdk/context` | उपलब्ध, SDK module के भीतर |
| **Node.js** | — | योजना में |
| **Rust** | — | योजना में |
| बाकी कुछ भी | ऊपर के वेरिएबल | आज |

:::note Go `lib/` में नहीं रहता
Go का context सपोर्ट उसी `sdk/` module में रहता है जिसे प्रोजेक्ट पहले से प्रकाशित करता है, एक उप-पैकेज के
रूप में जो उसे न import करने वाले के लिए शून्य हो जाता है। `lib/go-context` का मतलब होता एक ऐसे पैकेज के लिए
दूसरा Go module जिसका एक है ही।

नियम है **हर उस भाषा के लिए एक डायरेक्टरी जिसका प्रकाशित आर्टिफ़ैक्ट पहले से नहीं है**।
:::

हर लाइब्रेरी अपने संस्करण और tag वाला अलग आर्टिफ़ैक्ट है: Python क्लाइंट में सुधार engine का release ज़रूरी नहीं
करता।

## ये क्या हैं, और क्या नहीं

ये **अनुबंध के ऊपर पतले क्लाइंट** हैं, Go SDK के पोर्ट नहीं।

SDK की ETL मशीनरी का पोर्ट — drivers, pagination, checkpoints, ingestion ids — यहाँ का नहीं है और शायद कहीं
का नहीं: जिन भाषाओं को यह निशाना बनाता, उन सबके पास इसके लिए पहले से बेहतर टूल हैं, और Brevis का काम उन्हें
चलाना है। इसीलिए Python लाइब्रेरी है, ताकि टीम pandas, Polars या dbt इस्तेमाल करे और फिर भी वह एक चीज़ पाए
जिसके लिए ऑर्केस्ट्रेटर होता है।

## मेट्रिक्स

लाइब्रेरी मेट्रिक्स **उत्सर्जित** करती है, और उन्हें उजागर engine करता है:

```python
from brevis import metrics

metrics.set("rows_loaded", 48213)      # a gauge: the last value wins
metrics.inc("vendor_rejected_total")   # a counter: it adds up
```

वे **engine के** `/metrics` से निकलते हैं, शेड्यूलर के port पर, workflow और step के label के साथ — देखें
[ऑब्ज़र्वेबिलिटी](/hi/docs/observability/index.md)।

**यह कोई port नहीं खोलता, और खोल भी नहीं सकता।** Step अपने pod में चालीस सेकंड चलकर निकल जाता है; उसका खोला
port कभी scrape नहीं होता, या संयोग से एक बार होता। इसलिए पंक्ति stdout पर जाती है — उसी pipe पर जिसे engine
pipeline के चरण बनाने के लिए पहले से पढ़ता है — और engine उसे दर्ज करता है। इंस्टॉल करने को कुछ नहीं, चलाने
को कुछ नहीं, और label engine के होते हैं क्योंकि step अपना workflow slug नहीं जान सकता।

API का विवरण [Python](/hi/docs/python/#metrics-only-your-pipeline-knows) में है।

## किसी और भाषा के लिए क्लाइंट लिखना

अगर आप Node.js या Rust पर हमसे पहले पहुँच जाएँ, तो क्लाइंट को ये बातें सही रखनी होंगी — और जो Python
कार्यान्वयन कठिन तरीके से पहले ही सीख चुका है:

1. **Step से योग्य बनाई गई keys।** बिना step वाला `get("bucket")` मना होना चाहिए। दो steps `bucket`
   प्रकाशित कर सकते हैं, और खोजकर एक चुनना संयोग से बनी प्राथमिकता है।
2. **Writes को मर्ज करें।** अलग keys वाली दो कॉल दोनों रखती हैं; एक ही key दो बार हो तो आखिरी रहती है।
3. **सिर्फ़ प्रोसेस के निकलने पर flush करें।** जो step बुरी तरह मरता है वह कुछ प्रकाशित नहीं करता —
   जो सही है, क्योंकि क्रैश हुए step का आउटपुट उस काम का वर्णन करता जो पूरा नहीं हुआ।
4. **4096 बाइट से ऊपर मना करें।** प्लैटफ़ॉर्म मना करने के बजाय **छाँटता** है, और आधा कटा ऑब्जेक्ट अगले step
   को अमान्य JSON की तरह पहुँचता है।
5. **Brevis के बाहर भी काम करें।** `BREVIS_INPUT` न हो तो `get()` डिफ़ॉल्ट लौटाता है और `set()` बिना त्रुटि
   उठाए स्वीकार करके फेंक देता है: जिस स्क्रिप्ट को हाथ से चलाया नहीं जा सकता, उसे विकसित नहीं किया जा सकता।
