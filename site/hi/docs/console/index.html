दस्तावेज़

Console

Core का वेब इंटरफ़ेस: क्या चल रहा है, क्या चलेगा, और हर run के साथ क्या हुआ।

इंटरफ़ेस बाइनरी में ही आता है — कोई अलग service नहीं जिसे इंस्टॉल करके ज़िंदा रखना पड़े। सफलता दर, औसत अवधि, कतार, प्रयासों का इतिहास और आगे क्या आता है उसका शेड्यूल।

Console brevis serve के साथ उठता है, HTTP API वाले ही port पर (BREVIS_HTTP_ADDR, डिफ़ॉल्ट :8080)। क्विकस्टार्ट में वह localhost:8080 पर खुलता है।

नीचे की स्क्रीन console से नमूना डेटा के साथ SVG में दोबारा बनाई गई हैं — स्क्रीनशॉट कभी नहीं: असली console production में ग्राहकों का डेटा चलाता है।

अवलोकन#

मेट्रिक्स और चार्ट वाला अवलोकन। सफलता दर, औसत अवधि, जो जारी है और आगे के शेड्यूल किए गए run, एक स्क्रीन पर।

Workflows#

खोज, फ़िल्टर, pause और run वाली workflow की सूची। हर पंक्ति में cron, अगला और पिछला run, और tags होते हैं।

एक workflow#

Steps और निर्भरताएँ, पैरामीटर के साथ चलाने का फ़ॉर्म, हर step की स्थिति के साथ DAG, और साल का कैलेंडर जिसमें हर दिन अपने सबसे बुरे नतीजे का रंग लेता है।

Run#

Run का इतिहास, हर एक के प्रयास के साथ। स्थिति, workflow, trigger, run जिस slot का है वह, अवधि और बनने का समय।

एक run#

Run का लाइव DAG, और engine ने उसके लिए जो auto params निकाले। हर step की कमांड, image और अवधि के साथ ग्राफ़, और हर step का आउटपुट।

प्रोजेक्ट#

प्रोजेक्ट, ताकि दो टीमें एक नाम पर न टकराएँ। हर प्रोजेक्ट अपने workflows का namespace बनाता है: दोनों में एक-एक daily_ingest हो सकता है।

यह बाइनरी में आता है#

फ़ॉन्ट और bundles बाइनरी से परोसे जाते हैं — इंटरनेट के बिना काम करता है।
