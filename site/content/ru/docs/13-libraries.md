От оркестратора шагу нужны две вещи: **то, что опубликовал предыдущий шаг**, и
**какие часы должен читать этот запуск**. Клиентские библиотеки передают эти
две вещи и больше ничего.

## Контракт важнее библиотек

Engine определяет **две переменные окружения и файл**:

| | |
|---|---|
| `BREVIS_INPUT` | `{"<step id>": {…}}` — что опубликовали зависимости этого шага |
| `BREVIS_OUTPUT` | путь, по которому нужно записать **один** JSON-объект |

Плюс переменные запуска и автоматические параметры, все только для чтения:
`BREVIS_RUN_*` и `BREVIS_AUTO_*`. В Kubernetes `BREVIS_OUTPUT` — это
`/dev/termination-log`, который engine и так читает, чтобы получить код
завершения.

Поэтому **ни вызова API, ни токена, ни порта** не нужно. Шаг на любом языке
участвует с помощью разбора JSON и записи файла:

```bash
window=$(jq -r '.extract.watermark' <<< "$BREVIS_INPUT")
./publish --until "$window"
jq -n --arg n "$(date -Is)" '{published_at: $n}' > "$BREVIS_OUTPUT"
```

Библиотека здесь не открывает новых возможностей — она избавляет вас от
валидации, обработки отсутствующих значений и сообщений об ошибках, которые не
стоит писать заново.

## Какие есть

| язык | | |
|---|---|---|
| **Python** | `pip install brevis` | [доступна](/docs/python/) — `0.2.1` на PyPI |
| **Go** | `brevis/sdk/context` | доступна, внутри модуля SDK |
| **Node.js** | — | запланирована |
| **Rust** | — | запланирована |
| любой другой | переменные выше | сегодня |

:::note Go не живёт в `lib/`
Поддержка контекста для Go находится в модуле `sdk/`, который проект уже
публикует, как подпакет, не попадающий в сборку у тех, кто его не
импортирует. `lib/go-context` означал бы второй модуль Go для пакета, у
которого он уже есть.

Правило таково: **по одному каталогу на язык, у которого ещё нет опубликованного
артефакта**.
:::

Каждая библиотека — отдельный артефакт со своей версией и тегом: исправление
в клиенте для Python не вынуждает выпускать новую версию engine.

## Чем они являются и чем нет

Это **тонкие клиенты поверх контракта**, а не порты Go SDK.

Порт ETL-механизмов SDK — драйверов, пагинации, контрольных точек, ingestion id
— здесь не к месту и, вероятно, не к месту нигде: у каждого языка, для которого
это могло бы быть сделано, уже есть инструменты лучше, а задача Brevis — их
запускать. Поэтому библиотека для Python существует для того, чтобы команда
могла использовать pandas, Polars или dbt и при этом получать то единственное,
для чего нужен оркестратор.

## Метрики

Библиотека **выпускает** метрики, а публикует их engine:

```python
from brevis import metrics

metrics.set("rows_loaded", 48213)      # a gauge: the last value wins
metrics.inc("vendor_rejected_total")   # a counter: it adds up
```

Они появляются в `/metrics` **engine**, на порту планировщика, с метками
workflow и шага — см. [Наблюдаемость](/docs/observability/).

**Это не открывает порт, и не могло бы.** Шаг работает в собственном pod сорок
секунд и завершается; открытый им порт был бы опрошен ни разу или один раз по
везению. Поэтому строка уходит в stdout — тот же канал, который engine и так
читает, чтобы рисовать фазы пайплайна, — и engine её записывает. Ничего не
нужно устанавливать, ничего не нужно обслуживать, а метки — метки engine,
потому что шаг не может знать slug собственного workflow.

Подробности API — в разделе [Python](/docs/python/#метрики-которые-знает-только-ваш-пайплайн).

## Как написать клиент для другого языка

Если вы доберётесь до Node.js или Rust раньше нас, вот что клиент обязан делать
правильно — и чему реализация на Python уже научилась на собственных ошибках:

1. **Ключи, квалифицированные шагом.** `get("bucket")` без указания шага должен
   отклоняться. Два шага могут опубликовать `bucket`, а выбор одного поиском —
   это приоритет по случайности.
2. **Объединять записи.** Два вызова с разными ключами сохраняют оба; один и
   тот же ключ дважды сохраняет последний.
3. **Сбрасывать только при завершении процесса.** Шаг, жёстко упавший, ничего
   не публикует — и это правильно, потому что вывод упавшего шага описывал бы
   незавершённую работу.
4. **Отклонять больше 4096 байт.** Платформа **усекает**, а не отклоняет, и
   вдвое обрезанный объект приходит следующему шагу как невалидный JSON.
5. **Работать вне Brevis.** Без `BREVIS_INPUT` `get()` возвращает значение по
   умолчанию, а `set()` принимает и отбрасывает, не вызывая исключения:
   скрипт, который нельзя запустить вручную, нельзя разрабатывать.
